# AI-Based Indian Options Trading System — Development Specification

## 1. Project Objective

Build a production-quality Python-based AI/ML trading research and paper-trading platform for the Indian stock market, initially focused ONLY on:

* NIFTY 50 index options
* Angel One SmartAPI as the broker/data provider
* Option buying
* Defined-risk option selling using spreads
* AI/ML-based market-regime classification and trade filtering
* Paper trading first
* Real-money automated trading ONLY after extensive validation

The objective is NOT to create a "prediction bot" that blindly predicts whether NIFTY will go up or down.

The objective is to build a quantitative system that:

1. Collects market and options data.
2. Generates meaningful features.
3. Identifies the current market regime.
4. Estimates probabilities of future NIFTY movement.
5. Selects an appropriate options strategy.
6. Calculates expected value.
7. Applies strict risk management.
8. Executes paper trades.
9. Measures performance after realistic transaction costs and slippage.
10. Eventually supports live Angel One execution, but ONLY after paper-trading validation.

IMPORTANT:

* Do not implement live order execution initially.
* All trading functionality must default to PAPER mode.
* Never use real money without an explicit configuration change.
* Build the architecture so live execution can be added later without changing the strategy logic.

# 10. Prevent Data Leakage

This is CRITICAL.

Never use future information.

Every feature at time T must be calculated ONLY using information available at or before T.

Examples of forbidden leakage:

- using the day's closing price to make a 10:00 AM prediction
- using future option prices
- using future OI
- calculating normalization using future data
- randomly splitting time-series data

All ML datasets must respect chronological ordering.

---

# 11. ML Objective

Do NOT initially ask the model:

"Will NIFTY go up?"

Instead predict multiple outcomes.

Example:

At time T:

P(NIFTY rises >= 0.30% within next 30 minutes)

P(NIFTY falls >= 0.30% within next 30 minutes)

P(NIFTY remains within range)

These thresholds must be configurable.

Example output:

{
    "bullish_probability": 0.67,
    "bearish_probability": 0.14,
    "range_probability": 0.19
}

The model should also provide confidence/calibration metrics.

# 13. Market Regime

Create a regime classifier.

Initial regimes:

1. STRONG_BULLISH
2. BULLISH
3. STRONG_BEARISH
4. BEARISH
5. RANGE
6. HIGH_VOLATILITY
7. UNCERTAIN

The regime should consider:

- trend strength
- volatility
- momentum
- options positioning
- IV
- time of day

The AI should NOT be forced to produce a trade.

"NO TRADE" is a valid and desirable output.

# 14. Strategy Engine

Create three initial modes.

## Strategy A — Option Buying

Used primarily during strong directional regimes.

Bullish example:

- ATM Call
- or 1-strike ITM Call

Bearish example:

- ATM Put
- or 1-strike ITM Put

Selection should consider:

- liquidity
- bid/ask spread
- volume
- OI
- IV
- delta
- theta
- expiry

Avoid far OTM options.

---

# 15. Strategy B — Defined-Risk Option Selling

Do NOT implement naked option selling initially.

Use credit spreads.

Example bullish:

SELL NIFTY Put
BUY lower-strike NIFTY Put

Example bearish:

SELL NIFTY Call
BUY higher-strike NIFTY Call

Before entering calculate:

- maximum profit
- maximum loss
- breakeven
- risk/reward
- probability of profit
- estimated transaction costs
- estimated slippage
- expected value

Reject trades where maximum loss or expected value is unacceptable.

---

# 16. Strategy C — No Trade

The system MUST be allowed to stay flat.

For example:

If:

bullish = 0.40
bearish = 0.35
range = 0.25

Then:

NO TRADE

Do not force a position.

---

# 17. Strategy Selection

Implement a regime-based decision engine.

Conceptually:

STRONG_BULLISH
    → Option Buying

STRONG_BEARISH
    → Option Buying

BULLISH
    → Option Buying if confidence sufficient

BEARISH
    → Option Buying if confidence sufficient

RANGE + high IV
    → Defined-risk credit spread

HIGH_VOLATILITY
    → Special rules / potentially NO TRADE

UNCERTAIN
    → NO TRADE

Make thresholds configurable.

---

# 18. Expected Value

Every trade must calculate expected value.

Conceptually:

Expected Value =
Probability of Win × Average Win
-
Probability of Loss × Average Loss
-
Transaction Costs
-
Slippage

Do not execute a trade merely because the model probability exceeds 50%.

Require an adequate edge over costs.

# 21. Kill Switch

Implement an emergency kill switch.

Conditions can include:

- daily loss limit reached
- abnormal market movement
- stale market data
- broker API failure
- WebSocket disconnected
- order status unknown
- excessive slippage
- unexpected position
- system health failure

When triggered:

1. Stop new trades.
2. Log the reason.
3. Alert the user.
4. In LIVE mode eventually support controlled position handling.

For paper trading, simply stop opening new positions.

# 34. Important Research Philosophy

Do not optimize solely for maximum returns.

Optimize for:

- positive expectancy
- consistency
- low drawdown
- robustness
- realistic execution
- stability across market regimes

A strategy with:

30% annual return
and
8% drawdown

may be preferable to:

70% annual return
and
40% drawdown.

---

# 35. Avoid Overfitting

Do NOT repeatedly tune parameters against the test period.

If a parameter is changed because of test results, that period becomes part of development data.

Maintain:

TRAINING DATA

VALIDATION DATA

FINAL UNTOUCHED TEST DATA

Keep a record of model versions and parameters.

---

# 36. AI Should NOT Control Everything

Use deterministic rules where appropriate.

AI:

- estimates probabilities
- classifies regime
- filters trades

Deterministic code:

- selects valid contracts
- calculates risk
- calculates quantity
- enforces limits
- handles orders
- prevents dangerous behavior

Never allow an ML model to bypass the risk engine.

---

# 37. No Guaranteed Profit Claims

The application and README should explicitly state:

- This is experimental trading software.
- Backtested performance does not guarantee future results.
- Paper-trading results do not guarantee live performance.
- Options trading involves substantial risk.
- AI predictions are probabilistic.
- Transaction costs and slippage can materially reduce returns.

Do not advertise the system as a guaranteed income generator.

# 42. Critical Rule

The goal is NOT:

"Build me a profitable trading bot."

The goal is:

"Build me a scientifically testable quantitative trading platform that can determine whether a potentially profitable edge exists."

If the research demonstrates that the strategy has no reliable edge, the correct result is to report that honestly rather than artificially tuning the model until the backtest looks profitable.
